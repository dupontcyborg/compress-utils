A unified, high-performance interface for eight compression algorithms — **Zstandard, Brotli, zlib, bzip2, LZ4, XZ/LZMA, Snappy, gzip** — exposed identically across multiple languages.

```
           ┌──────────────────────────────────────────┐
Your app → │  C / C++ / Go / JS / Python / TS / Rust  │
           └────────────────────┬─────────────────────┘
                                │
                      ┌─────────▼──────────┐
                      │   compress-utils   │
                      └─────────┬──────────┘
                                │
    ┌───────┬───────┬───────┬───┴───┬───────┬───────┬───────┐
  zstd   brotli   zlib    gzip     bz2     lz4     xz    snappy
```

## Same API, every language

```python
cu.compress(data, "zstd", level=5)                    # Python
```

```ts
await compress(data, { level: 5 })                    // JavaScript / TypeScript: import from "compress-utils/zstd"
```

```go
cu.Compress(cu.Zstd, data, 5)                         // Go
```

```rust
compress(Algorithm::Zstd, data, 5)?                   // Rust
```

```cpp
cu::compress(cu::Algorithm::Zstd, data, 5);           // C++
```

## Supported algorithms

<!-- BEGIN:algorithms -->
<!-- Generated by tools/check-readmes.py from docs/readme/manifest.json. Edit the manifest and run `tools/check-readmes.py --fix`, not this block. -->

| Algorithm                                          | Strength                   | Wire format produced                                                     |
|----------------------------------------------------|----------------------------|--------------------------------------------------------------------------|
| [Zstandard](https://github.com/facebook/zstd)      | High speed, high ratio     | ZSTD frame with content size                                             |
| [Brotli](https://github.com/google/brotli)         | Web-optimized              | Raw Brotli stream                                                        |
| [zlib](https://github.com/madler/zlib)             | Ubiquitous                 | zlib wrapper (RFC 1950)                                                  |
| [gzip](https://www.gnu.org/software/gzip/)         | Ubiquitous (.gz files)     | gzip stream (RFC 1952)                                                   |
| [bzip2](https://sourceware.org/bzip2)              | High ratio                 | bzip2 stream                                                             |
| [LZ4](https://github.com/lz4/lz4)                  | Highest speed              | LZ4 frame (interoperable with the `lz4` CLI and `.lz4` files)            |
| [XZ / LZMA](https://github.com/tukaani-project/xz) | Highest ratio              | XZ stream with CRC64                                                     |
| [Snappy](https://github.com/andikleen/snappy-c)    | Very high speed, low ratio | Raw Snappy block (interoperable with reference snappy and python-snappy) |

Raw block formats, for reading data from other tools:

| Format                                                                   | Wire format                                                                              |
|--------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| [DEFLATE](https://www.rfc-editor.org/rfc/rfc1951)                        | Raw DEFLATE (RFC 1951), no wrapper                                                       |
| [LZ4 block](https://github.com/lz4/lz4/blob/dev/doc/lz4_Block_format.md) | Raw LZ4 block, no frame or size prefix (one-shot compression, incremental decompression) |
| [LZO1X](https://www.oberhumer.com/opensource/lzo/)                       | Raw LZO1X block (decompression only)                                                     |
<!-- END:algorithms -->

For reading data from other tools, three raw block formats are available (`deflate`, `lz4_raw` and `lzo`). Raw blocks don't record their decompressed size, so every binding's `decompress` accepts an output capacity. It's fastest to pass one. Without it, `lz4_raw` is decoded with the slower incremental stream decoder. Code from each codec is credited in [`ACKNOWLEDGMENTS.md`](ACKNOWLEDGMENTS.md), and the license texts are in [`THIRD_PARTY_NOTICES.md`](THIRD_PARTY_NOTICES.md).

All algorithms expose the same API surface and the same level scale (`1` fastest → `10` smallest). The library maps each user level to the algorithm's native range so you don't need to remember that ZSTD goes 1–22 and zlib goes 1–9.

## Benchmarks

![throughput by language and algorithm](benchmarks/assets/lang-comparison.png)

All eight codecs across the C, JS/TS, Python, Go, and Rust bindings, measured back-to-back in one interleaved run. Every binding drives the same C core, so compression ratio is byte-identical across languages — only throughput differs, and C, Rust, and Python land on top of each other.

Full methodology, per-corpus Pareto plots, and how to reproduce are in [benchmarks/README.md](benchmarks/README.md).
